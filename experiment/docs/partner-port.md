# PartnerPort とモック実装

> **legacy。** 旧ブラウザ内モック版（`#/legacy`）の `PartnerPort` です。現行DEMOの将来のAI接続口はサーバー側の `worker/partners/types.ts`（`PartnerAdapter`）で、[`agent-protocol.md`](agent-protocol.md) に記載しています。

`PartnerPort` は会話相手との境界です。UIと実験フローは `respond` と `submitNames` のみを呼び、具体的な相手実装に依存しません。現在の `MockPartner` は動作確認用の決定規則で返答と最終提出を作ります。画像理解は行わず、研究結果ではありません。実験刺激や対話方略の妥当性を示すものでもありません。

## 依存の向き

将来の内部処理では、知覚・判断の契約を自然言語生成から独立させます。知覚・判断側は画像の候補解釈や確認の要否などの内部情報を定め、自然言語生成側がそれを会話文にします。両者を交換可能な別コンポーネントとして扱い、UIは引き続き `PartnerPort` だけに依存します。参加者向け画面へ内部候補や診断情報を渡しません。

## 将来の単一マルチモーダルモデル

将来、画像解釈と「今確認するか」の判断を単一のマルチモーダルモデルにまとめる場合も、モデル呼び出しはサーバー側の `PartnerPort` 実装に閉じ込めます。サーバーが画像と会話履歴を受け取り、自然文応答と独立した最終命名を返します。鍵、画像アクセス、内部状態、採点用IDをブラウザーに置きません。今回のモックからモデルの知覚能力や認知過程を推論できません。

## 本番での配置・採点ID境界案

- ブロックごとにランダムな不透明 `slotToken` を発行し、相手側のスロットと提出名を対応づけます。
- 採点用の刺激IDと相手用配置の対応表はサーバーだけで保持します。ブラウザーには人間側の表示に必要な画像とUIデータだけを返します。
- 相手側の配置、相手の `slotToken`、採点用ID、条件ラベルを参加者向けAPI応答・イベント・エラー文・画面に含めません。
- 最終提出をサーバーで受け、サーバー上の対応表で採点データへ接続します。結果を開示する場合は、所定の質問紙が完了するまで正誤を返しません。
- ブラウザーの開発者ツールや保存データから相手配置を再構成できないことを、本番のアクセス制御と漏洩テストで確認します。

この境界は本番実装時にレビュー・検証が必要な提案です。現在のデモはブラウザー内で動くため、本番実験や参加者データ収集には使用できません。
