# タングラム共同命名 v2（Cloudflare公開版）

操作確認用URL：<https://tangram-grounding-experiment.kame-website.workers.dev/>

このページは6図形の共同命名課題のプロトタイプであり、正式な実験プロトコルではありません。研究目的・比較条件は [研究計画の正本](../../dialogue-model/README.md) を参照してください。

## 構成

公開サーバーのエントリポイントは `src/index.ts`（TypeScript）です。Cloudflare Workers と Durable Object で試行・対話・非公開AI判断・提出と暫定採点を扱います。対話ロジックは既存の `dialogue-model/runtime/v2/` のJavaScriptモジュールを再利用します。現段階で研究用コアロジックは全面的にはTypeScriptへ移行していません。

静的アセットは `build-assets.mjs` で既存のHTML/JS/CSSだけを `dist/` にコピーします。公開ワーカーから研究データ、 `.env`、内部コードを配信しません。

AIは同一Cloudflareアカウント内のサービスバインディング `AI_PROXY` を通して呼び出します。既存の `dialogue-grounding-ai-proxy` に `InternalResearchProxy` という内部エントリポイントを追加し、モデル選択、接続認証、上流APIキーは従来のAI Worker内で保持します。

公開ページは認証なしで開けます。実験参加者の操作を妨げない範囲でBot由来の大量アクセスのみ抑制します。APIキーは公開されず、Cloudflare内部の既存AI Workerだけが保持します。

## デプロイ

```sh
npm ci
npm run build:tangram
npx tsc -p workers/research-ai-proxy/tsconfig.json
npx tsc -p workers/tangram-experiment/tsconfig.json
npm test
npm run deploy:research-proxy  # 内部エントリポイント変更時のみ
npm run deploy:tangram
```

公開Workerへのアクセスコード登録は不要です。AIプロキシのSecretをこの公開Workerに複製する必要もありません。旧版v1はローカルNodeサーバーの `/v1/` で利用できますが、公開URLではv2のみを提供します。

## 緩いBot対策

公開ページにはログイン・CAPTCHA・会話時間制限・総発話回数制限を設けません。CloudflareのRate Limiting bindingを使用し、短時間に異常な回数の操作が起こった場合だけHTTP 429を返します。

- 試行開始：同じIPから40回／60秒
- AIを利用する操作（発話送信・再試行・名前提出など）：同じブラウザセッションで30回／60秒、同じIPで120回／60秒、Cloudflare拠点全体で300回／60秒
- 画面表示、画像やスクリプト取得、会話履歴更新（GET `/api/state`）：制限なし

同じネットワークを共有する被験者にも影響しにくいよう余裕を設けています。429の際は `Retry-After: 60` を返します。検索エンジンに対しては `robots.txt` と `X-Robots-Tag: noindex` を返します。これは検索対策であり、アクセス遮断ではありません。レート制限はCloudflare拠点ごとの概算カウンターであり、世界的な厳密な上限や支出上限にはなりません。

## 研究者用ログページ（`/admin`）

研究者だけが、試行の一覧と詳細（公開発話、ターンごとの判断、実行の記録とエラーコード、外部要求の段階と遅延、生成ガード、提出と採点）を読み取りで確認できます。参加者向けのAPIと画面は変わりません。`/api/state` が返す内容も増えていません。

- 認証：Worker Secret `ADMIN_TOKEN`（32文字以上のランダム値）。`Authorization: Bearer <token>`、またはBasic認証（ユーザー名 `researcher`、パスワードにトークン）で送ります。ブラウザではBasic認証の入力欄が出ます。URLのクエリにトークンを入れても無視します。
  - Secretが未設定、32文字未満、またはレート制限のbindingがない場合、`/admin` は404を返します（fail closed）。
  - 認証情報を伴う要求は、正誤にかかわらず同じIPから30回／60秒まで（`ADMIN_RATE_LIMIT`）。超えると429です。
  - 応答には `Cache-Control: no-store`、`X-Robots-Tag: noindex`、スクリプトを一切許可しないCSPを付けます。CORSは許可しません。
- 設定：`npx wrangler secret put ADMIN_TOKEN --config workers/tangram-experiment/wrangler.jsonc`（研究者が実行）。トークンはリポジトリ・ログ・URLに書かないでください。
- 一覧は試行（recordId）ごとで、同じブラウザでの過去の試行も表示します。更新が新しい順に1ページ100件で、状態・エラー・参照メモリで絞り込めます（絞り込みは表示中のページ内に適用）。

## 保存されるデータと保持期間（暫定）

最終的なデータ保持方針は研究者が決めます。それまでの暫定の既定として、**記録は最終更新から30日後に自動削除**します。

| 保存先 | 内容 | 削除 |
| --- | --- | --- |
| 各ブラウザの `TangramSession`（Durable Object）の `record:<recordId>` | 試行ごとの完全な記録（公開発話、非公開の判断・実行記録、外部要求、提出、採点と正解表）。新しい試行を始めても過去の記録は残ります | 最終更新から保持期間が過ぎたとき、または研究者が削除したとき |
| 同じDurable Objectの `active` | このブラウザで再開する試行（`record:` と同じ内容） | 同上（その試行の記録が消えるときに一緒に消える） |
| 同じDurable Objectの `ledger`・`tombstones` | recordIdと最終更新時刻だけ／削除済み（研究者による削除・期限切れ）のrecordIdだけ（内容なし） | 自動削除しない |
| `AdminIndex`（Durable Object、全体で1つ）の `r:` と `u:` | 一覧用の要約（recordId、Durable Object ID、開始・更新時刻、方略、参照メモリ、発話様式、状態、件数、エラーコード、遅延の集計）。Cookie・IP・User-Agent・発話本文・名前は含みません | 対応する記録と同時に削除 |
| `AdminIndex` の `a:`・`d:` | 削除の監査記録（recordIdのハッシュ、削除日時、理由 `admin` / `retention`）。内容は含みません | 自動削除しない |

- 自動削除：各 `TangramSession` は、記録のうち最も早く期限を迎えるものの時刻にDurable Objectのalarmを設定し、記録を保存するたびに設定し直します。alarmでは期限を過ぎた記録だけを削除し、その前に `AdminIndex` から該当項目を消します。`AdminIndex` から消せなかった場合は記録も消さず、alarmの再試行に任せます。期限前に削除することはありません。期限内の試行は従来どおり再開できます。セッションを再開するときは、移行（下記）→期限切れの削除→alarmの設定→再開の順に処理するため、期限切れの試行は再開されません。期限切れで削除した試行のIDは削除済みとして記録し、同じ試行が後から保存しようとしても記録も一覧の項目も作り直しません。
- 一覧と記録の対応：一覧の項目は記録と同時に削除されます。一覧への登録は記録の保存とは別の処理で、失敗しても参加者の試行には影響しません。登録に失敗した記録は、そのセッションの次の再開時とalarmのたびに登録し直します。削除済み（研究者による削除・期限切れ）のIDは、一覧に再登録しません。
- 期間の変更：`wrangler.jsonc` の `RECORD_RETENTION_DAYS`（1〜365の整数、不正な値は30）を変えてデプロイします。新しい期間は、各セッションのalarmが次に設定されるとき（次の保存、アクセス、またはalarm）から適用されます。
- 研究者による削除：記録の詳細ページ下部で、確認欄に記録IDを入力して削除します。認証済みのPOSTで、同じオリジンからの要求であること（`Origin` 必須。`Origin` がこのサイトか、`null` の場合はブラウザが付ける `Sec-Fetch-Site: same-origin` を必須）と確認欄の一致を確かめます。管理ページは `Referrer-Policy: same-origin` を返すので、通常のブラウザは送信時に正しい `Origin` を付けます。GETでは削除しません。削除すると、まずセッション側の記録・`active`（その試行の場合）を消し、次に一覧の項目を消して、内容のない監査記録を残します。2段目で失敗した場合は、記録は既に消えたまま一覧に項目だけが残ります（詳細は「記録がありません」）。同じ削除をもう一度実行すれば項目も消えます。実行中の試行が後から保存しようとしても書き戻されません。
- 既存セッションの移行：この変更より前の `active` だけを持つセッションは、次にアクセスされたときに一度だけ `record:<recordId>` に複製して一覧に登録し、最終更新から期限を設定します（追加のみ）。**一度もアクセスされない古いセッションは、一覧にも自動削除の対象にも入りません**。Durable Objectを列挙する手段がないためです。また、この変更より前に同じブラウザで置き換えられた試行の記録は既に失われており、復元できません。
- 上記以外にデータを消す処理はありません（Durable Objectの退避はメモリを解放するだけで、保存内容は消えません。`deleteAll` は使っていません）。

## 制限

操作確認用です。正式な同意取得、質問紙、参加者管理、研究データの確実なエクスポート機能は未実装です。試行データは個別のDurable Objectに格納します。同じブラウザで新しい試行を開始すると再開対象（`active`）は新しい試行に替わりますが、過去の試行の記録は保持期間のあいだ残ります。研究倫理とデータ保持方針、実験条件を確定するまでは一般募集に使用しないでください。
