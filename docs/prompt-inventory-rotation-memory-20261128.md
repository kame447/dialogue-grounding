# プロンプトの棚卸しと整理（回転別観察メモ・並列C）

2026-11-28、担当: C（HappySomerville、claude-sonnet-5-5）。基点: `471a11b`（B2 の 4e09b62 移植）＋ main `1731cce`（B2 の `9278d98`）＋ B1 の束 `e2065a6`・`cd7f326`＋ B2 の配線 `3c8fa0e`。研究者の追加指示「既存プロンプトの重複・矛盾解消（必須）」への対応記録である。実 API は呼んでいない（組立済みの要求を模擬の応答でオフラインに捕捉した）。

## 0. 要約

- 回転別メモ（`rotation`）の意味の説明は `decision/rotation-memory-guidance.ts` の1か所に定義し、各呼び出しは**データの隣に1回だけ**凡例を置く。凡例は自分の想像（向きを変えて見たらどう見えるか）の定義だけで、相手の向き・回転方式には触れない。相手の盤面が回転して提示される課題条件は既存の `rotationPremise`（`ROTATION_V5`・`ROTATION_V5_90_180_270`）が従来どおり担い、3つの回転方式でバイトは不変。
- 切替は「メモの図形に `rotation` があるか」の1つの判定だけ。無い要求は旧版のバイトのまま（旧版のバイト固定の試験は基点と同じ結果）。
- 新しい版で**置換・削除**したもの: 再観察を先に促す文（`request_observation` の「別の見立て」「初期観察メモの向き・見え方が食い違い…優先して選ぶ」、共通文の「必要なら画像の再観察を選べます」）、`accept`・`confirm`・`propose_name` の基準の重複、生成の「自然な見立てがなければ全体の形でかまいません」。**追加**したもの: 凡例1つ、再観察を求めない条件、別の向きの見立てを自然に使う文、自分側の想像と相手の画面の向きの区別、抽出・再観察の各1文。新しい長い禁止リストや検査・停止の経路は足していない。
- 呼び出しごとに層を分けた（判断・再観察・局所抽出・AI 抽出＝名詞の層、生成＝役割の層）。6図形の判断の要求は基点 8.3k 字→4.6k 字、4e09b62 の移植のまま 18.4k 字（上限 20,000 字の目前）→4.6k 字（新しい版）。

## 1. 範囲と方法

- 対象: 初回の事前メモ、判断（Jev の action・target・human_referent・detail）、発話生成、局所抽出（相手の発話）、AI 抽出（AI 自身の発話）、再観察。実際に組み立てた要求を、v24 の新規受付と同じ構成（`holistic_v5`・`bypass_acceptance_v3`・`jev_repair_quality_v1`・`jev_generation_retry_v24`・`postGenerationCheck: off`）で、3場面（全体の問い／特徴の確認＋再観察／名前の合意）×両方略（repair-first・bypass-enabled）×3/4/6図形で捕捉した。
- 捕捉の道具: `tests/support/s4-v3-records.ts` の `runTurn`（実際の `createProfileDialogue` を走らせ、HTTP 本体を記録する）。再現の手順は付録B。スクリプトは `docs/prompt-inventory-rotation-memory-20261128/` に置いた。

- 字数は要求本文の合計（判断は state＋問いの instructions＋criteria）。概算トークン＝非ASCII 1文字を1、ASCII 3.5文字を1とした粗い見積もり（実測のトークナイザではない）。

## 4. 新しい版の設計

- **切替**: メモの図形のどれかに整形式の `rotation` があるか（`hasRotationMemory`、B1 の `validateOwnRotationMemory` で検査）。別の版フラグは判断・生成・抽出へ通さない。整形式でない `rotation` は無いものとして扱い、要求を止めない（新しい停止の経路を作らない）。旧受付は `rotation` を持たないので全呼び出しが従来のバイト。
- **責務**: 判断は対象と応答方針（回転別メモで答えられる問いは `accept` で直接答え、メモにない画像上の事実だけ再観察）、生成は自然な言語化（別の向きの見立てを「見る角度によっては〜」で添える）、抽出は公開発話の証拠との照合（別の向きの見立て・部分とも照合し、一致は確定でない）。見立ての一致だけで対象・合意・命名を確定しない。自分の仮想回転（向きを変えて見る）は自分側の想像で、相手の画面の向きの主張ではない。
- **層**（`ROTATION_LAYER_OF_CALL` の1か所。変える必要があれば根拠つきで統括へ）:

| 層 | 中身 | 使う呼び出し |
|---|---|---|
| 名詞（nouns） | 領域「領域id 形 面積の割合」、各向きを1行「全体: 見立て・見立て（中） / 領域id 部分の見立て…」（全体なしは「全体: なし」）、`wholeAnywhere`、`turned[].rel` | 判断（action・target・human_referent・detail・prospect）、局所抽出、AI 抽出、再観察 |
| 役割（roles） | 名詞の層＋領域の位置・頂点の向き・くぼみ・隣接の1行、全体の見立てごとの1行「見立て: 領域id 役割 / …」 | 発話生成 |
| 全体（full） | 役割の層＋姿勢・その見え方の中での向き | 既定では使わない |

  名詞・確信度の印（中・高のときだけ。省略は低）・領域ID・`wholeAnywhere` はどの層でも落とさない（全方向の候補を落とさない）。部分の持ち主（owner）は層に持たない。
- **凡例**: 層ごとに `ROTATION_LEGENDS` が1か所で定義し、各呼び出しがデータの隣の `rotationLegend` キーで1回だけ持つ（判断・抽出は state/context の JSON の中、生成・再観察も同じ）。凡例は自分の想像（向きを変えて見たらどう見えるか）の定義だけで、相手の盤面・回転方式・「どの向きが相手に近いか」には触れない。字数は 307（名詞）／416（役割）／437（全体）。
- **回転条件の文**（相手の盤面が回転して提示される）: 既存の `rotationPremise` が従来どおり担う。凡例とは別の文で、3つの回転方式で新しい版の回転別メモの部分（凡例・メモ・基準文）はバイト同一（試験 `the three rotation modes differ only…`）。
