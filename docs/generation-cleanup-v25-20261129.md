## 2. #273 consult と共通の文の食い違い: どちらを優先したか

優先したのは **consult の「自分側の観察の特徴は述べない」**。根拠:

1. consult は、同じ問題の修復が停滞または困難で、続けるか別の進め方にするかを自分では決めないとき、まだ合わせられていないことを伝えて相手に進め方を尋ねる行動である。自分からは移らず、**どちらにも誘導しない**。まだ確かめていない手がかりがあるうちは選ばれない（`decision/jev-decision.ts` の consult の定義）。選ばれるときは新しく述べる観察の特徴が残っておらず、特徴を足すと「確かめ続ける」側に誘導する。consult は方略（repair-first と bypass-enabled の代替）の操作の一部なので、文の中身を変えると操作の意味が変わる。
2. 共通の「質問するときも自分の見え方を添える」は、v24 の統括の定性の評価（commit 2e72b1e、「AI が問い続けて相手だけが説明する形を避ける」）で、図形について問う発話に足した文である。進め方を尋ねる発話に観察の特徴を足す意図は記録にない。
3. 回転別メモの棚卸し（`docs/prompt-inventory-rotation-memory-20261128.md` の G-4・G-5・§11.2）が、この食い違いを回転別メモと無関係として保持し、新しい版で整理する課題にした。

そのため共通の文を図形についての質問に限った。consult の文（`actionScopes.consult`）は v24 と同じ。

## 7. 見送ったこと・確かめていないこと

- **見送り（L×S < 15、実装せず）**: (1) 回転別メモのない要求の【形の参照枠】の「相手には形の対応を尋ねてください」と accept の「別の確認質問は足さない」の食い違い（G-7。回転別メモのある要求は既に解消済み。回転別メモのない新規受付は想定しない。L 2×S 3）。(2) ON の抽出が図形を知らない、抽出の層が位置を持たない問題（#275 の続き。既定は OFF。L 8×S 2 = 16 だが対処は抽出の入力の変更を伴い、研究者の ON の判断が先）。追加するなら、抽出に計画の図形を渡す（独立性を保てるか要検討）、計画外の図形の出所を捨てるのではなく不一致にする現在の扱いは保つ、のどちらかになる。
- **確かめていない**: 実際の対話での自然さ・質問の数・書き直し率・応答時間。v25 の `consult` が v24 より観察の特徴を足さなくなったか（v24 でも足していない）。「一点だけ」を外したことで質問の数が増えるか。ON の出所の一致率（4 組で 0）。実 API の試験は少数の単発の場面で、同系統のモデルによる評価。
- 切り替えの手順（統括向け）: Worker の `PARTICIPANT_DIALOGUE_PROFILE` を `participant_dialogue_v25_generation_cleanup` にすると、新しい受付の承認時に v25 が固定される（「生成後チェック」の既定は OFF、承認時に設定の値を固定）。承認済みの v24 以前の受付と進行中の試行は、保存された版のまま動く。戻すときは環境変数を戻す。
