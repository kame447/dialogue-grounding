## 2. #273 consult と共通の文の食い違い: どちらを優先したか

優先したのは **consult の「自分側の観察の特徴は述べない」**。根拠:

1. consult は、同じ問題の修復が停滞または困難で、続けるか別の進め方にするかを自分では決めないとき、まだ合わせられていないことを伝えて相手に進め方を尋ねる行動である。自分からは移らず、**どちらにも誘導しない**。まだ確かめていない手がかりがあるうちは選ばれない（`decision/jev-decision.ts` の consult の定義）。選ばれるときは新しく述べる観察の特徴が残っておらず、特徴を足すと「確かめ続ける」側に誘導する。consult は、bypass を採らない側の代替（confirm・repair・consult、`NON_BYPASS_ALTERNATIVES`）の一つで、方略の操作に関わる行動なので、文の中身を変えると操作の意味が変わる。
2. 共通の「質問するときも自分の見え方を添える」は、v24 の統括の定性の評価（commit 2e72b1e、「AI が問い続けて相手だけが説明する形を避ける」）で足された文で、図形の説明をやり取りする対話が対象である。進め方を尋ねる発話に観察の特徴を足す意図は記録にない（この対象の読みは、commit の記録からの推定）。
3. 回転別メモの棚卸し（`docs/prompt-inventory-rotation-memory-20261128.md` の G-4・G-5・§11.2）が、この食い違いを回転別メモと無関係として保持し、新しい版で整理する課題にした。

そのため共通の文を図形についての質問に限った。consult の文（`actionScopes.consult`）は v24 と同じ。
