# dialogue-annotation-jev

対話アノテーションを Jev で支援するための設計リポジトリです。

このリポジトリの目的は、既存の対話アノテーション基準を壊さずに、Jev の閉集合判断をどこへ導入できるかを先に設計・評価することです。現段階では実装を目的とせず、判断契約、文脈の渡し方、人間レビュー、評価方法、データ形式、プライバシー条件を固定することを優先します。

対象となるアノテーションは、発話機能 a1–a30、ずれ状態 M0–M4、調整過程 P1–P6、エピソード結果 ER0/ER1、エピソード境界、重なり発話です。これらは同じ意味階層ではないため、単一の分類問題として扱いません。

本設計では、M/P/ER とエピソード境界を Jev の主要な適用候補とします。発話機能は最小文字列範囲、複数ラベル、重なり発話、半開区間を扱う必要があるため、span 抽出とラベル判定を分離します。span 候補の抽出は生成モデルまたは決定的処理、候補ラベルの閉集合判定は Jev、最終確定は人間という構成を基本案とします。

現在の確定済み 5 対話は、基準作成にも使用されているため、独立した汎化性能の評価セットとはみなしません。これらは既存アノテーションとの互換性を確認する regression benchmark として使用し、将来の未使用対話を locked holdout として別に確保する方針です。

実データ、音声、完成済みアノテーションファイル、個人識別情報はこのリポジトリへ保存しません。examples には架空データだけを置きます。

## 現時点の基本方針

Jev を完成済みアノテータとして扱いません。Jev は閉集合判断を高速・安価・再現可能に行う一次判定器として扱い、人間の最終判断を置き換えません。

生成モデルを完全に排除することも目的にしません。任意 span の抽出、未解決局所問題の内容要約、必要に応じた文脈圧縮など、閉集合では表現しにくい処理だけを限定的に残します。

既存の運用基準を ground truth の定義源とし、Jev に合わせてラベル定義を単純化しません。モデル側の都合で基準を変えるのではなく、基準を満たせない処理は human review または生成モデル側へ戻します。

## 参考実装

主要な参考実装は AkashPriyadarshii/jev-curate です。設計確認時点では main の commit ea7048c1d2ff67253c3afa8fec7a0738983595cd を参照しています。jev-curate の streaming、speculative fan-out、rate limiting、audit log、manifest の考え方は流用候補ですが、keep/reject 中心のデータ curation と本研究の annotation は目的が異なるため、そのまま fork して設計を固定しません。
