# 局所命題単位の部分更新（opt-in・研究用）

[決定記録 0001](../../decisions/0001-partial-grounding-state.md) の設計原則を実装するための共通契約です。型と閉集合は [contract.ts](contract.ts) にあります。既定の実験条件・方略・採点・UI・モデルポリシーは変更しません。`createDialogueV2` で明示的に有効化した場合だけ動作し、両方略（repair-first / bypass-enabled）で同じ機構を使います。

## 責務

1. **Luna（抽出）**：現在の人間発話を節・部分に分け、引用、自分側の対象候補、論点（`LOCAL_ASPECTS`）、自由記述の命題、既存の局所問題・先行発話へのリンク候補を提案する。
2. **Jev（閉集合の機能判定）**：各部分が、どの先行命題に対する `LOCAL_ACTS` のどれかを文脈付きで選ぶ。判定できなければ `unknown`。生のスコアは研究記録だけに残し、昇格の閾値に使わない。
3. **プログラム（検証）**：引用が公開発話の字句であること、応答先の命題・発話が存在し論点と対象が整合すること、名称が字句として公開発話に出たことを検証し、通ったものだけを参照グラフの `claim` 操作にする。
4. **コミット**：`claim` 操作は同じターンの参照グラフ更新に含め、生成が成功し公開された時点でだけ適用する。失敗・中断・置換されたターンの解釈は反映しない。

## 検証規則（プログラム側の最低限）

- `agree` / `deny` / `name_accept` / `name_reject` / `withdraw` は、検証できた応答先（`respondsTo`）がある場合だけ記録する。応答先が無い・複数あり得る・論点や対象が一致しない場合は棄却し、他の命題は変更しない。
- 「うん」「それでいい」など相槌・指示語だけの部分は、直前の公開発話に応答先候補がちょうど1つある場合に限り、その命題へ結び付ける。そうでなければ `acknowledge` として記録するか棄却し、合意にしない。
- `construe`（「船っぽい」）は見立てであり、名称状態を変えない。名称状態は `aspect: "name"` の `name_propose` と、それに対する相手の `name_accept` / `name_reject` からだけ導く。
- 別の対象（slot）に対する名称提案への受諾は、現在の対象の名称合意に流用しない。
- 対象候補が未特定・複数の部分は、対象を確定させない（`targets: []` または複数候補のまま）。
- 状態（`LOCAL_ISSUE_STATES`、`LOCAL_NAME_STATES`）は記録から毎回導出し、別に保存しない。
- 履歴だけから、公開発話に支持されない同意を新設しない。AIの仮説（`ai_hypothesis`）は正解ではなく、`grounded` も真の指示対象同定を意味しない。

## 未決定
