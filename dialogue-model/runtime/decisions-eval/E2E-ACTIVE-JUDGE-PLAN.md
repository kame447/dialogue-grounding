# Active judge E2E 計画（実験外・診断専用・研究者未承認）

ブランチ `research/active-judge-e2e`（PR #19 `37a2fef` から分岐）。研究正本は [../../README.md](../../README.md)。この E2E はプロトタイプの動作確認であり、実験結果・方略効果・モデルの優劣の証拠ではありません。既定は無効で、通常の会話・shadow mode・repair-first / bypass-enabled の運用は変えません。

## 構成（active judge を明示的に有効にした場合だけ）

1. **Luna の解釈**（既存の判断呼び出しをそのまま使う）: 自分の画像・公開履歴・作業メモ・（任意）参照メモリから、対象候補 `targetSlot`、名前候補 `candidateName`、識別特徴 `discriminatingFeature`、メモ、`followUp`、`reference` を出す。Luna 自身が選んだ action は「Luna の提案」として記録するだけ。
2. **Decisions による行動選択**: shadow と同じ `buildDecisionEvidence`（公開発話・作業メモ・Luna の未検証仮説。Luna の action は含めない）を、選んだ判断モデル（`decision_jev` か `decision_luna`）に送り、9行動から1つを選ばせる。
3. **合成と検証**: 判断モデルの action と Luna の解釈の項目を合わせて、既存の `validateJudgment`（v2 の `agreeEvidence` を含む）で検証する。
   - action に不要な項目は外す（例: move_on・close では candidateName を null にする）。必要な項目がなければ無効とする。
   - Luna の action と異なる場合、`followUp` は使わない（後続の妥当性を保証できないため）。`reference` は人間の発話の解釈なので、検証を通れば残す。
   - **無効なら安全な再判定**: 追加の呼び出しはせず、判断モデルの確率の高い順に、検証を通る次の action を選ぶ。どれも通らなければ `accept`（合意を作らない）にする。
   - agree は検証を通った場合だけ成立する。判断モデルが agree を選んだだけでは合意にならない（未割当の対象への agree は既存の規則で拒否される）。
   - **保守的な合意ゲート**（BriskPasteur の監査を受けて）: 判断モデルの agree は、同じ回の Luna 自身の判断も同じ対象への agree である場合だけ有効にする。tentative は特徴のない提案からも生じるため、検証を通ることは共有された同定の証明にならない。判断モデルは合意を止める・遅らせることはできるが、自分から合意を始めることはできない。このため、この E2E では判断モデルが合意を始める能力は測れない。
4. **Luna の発話生成**: 確定した判断から、既存の生成器で日本語の発話を作る（変更しない）。
5. **下流の失敗**: 判断モデルの呼び出しが失敗（タイムアウト・402・不正応答）したら、その回だけ Luna 自身の判断をそのまま使う（従来の経路）。会話・状態・方略は壊さない。

記録（非公開の研究記録だけ）: Luna の提案 action、判断モデルの action と確率、最終 action、再判定の理由（`rerank`・`fallback`）、モデル、遅延、費用。参加者に返す状態には出さない。

**比較の性質**: 判断モデルは Luna の解釈（対象・名前・特徴の仮説）を受け取って行動だけを選ぶため、Luna から独立した判断モデルの比較ではない。画像は判断モデルに送らない（文章だけ）。

## 有効化

研究者が明示する設定だけで有効にする（例: サーバ起動時 `--active-decision-judge decision_jev`）。参加者の画面・API からは切り替えられない。既定は無効。

## 実 E2E の手順

- 刺激: 研究で生成した合成のタングラム6図形。AI はAI側の盤面だけ、人間役は人間側の盤面（ブラウザ画面）だけを見る。
- 人間役（Opus）は未見の seed を使い、AI盤面・正解表・非公開の作業メモ・評価結果を、最終提出まで見ない。自然な短い発話を1手ずつ送り、答えを先に渡さない。
- 6図形すべての名前について合意したと人間役が判断したら、双方が非公開で提出し、採点する。
- セッション1: Jev active。可能ならセッション2: Luna Decisions active を同じ seed・同じ役割で行う（人間役の学習バイアスを限界に記録する）。
- 記録: 一致数、途中の誤合意・誤修復・確認回数・保留・再訪、各モデルの判断頻度、Luna の提案との不一致、再判定・フォールバック数、遅延、費用、取り違えの例（要約のみ）。
- 費用: 研究キーの月$10上限内で小規模。送るのは合成図形と合成対話だけ。
