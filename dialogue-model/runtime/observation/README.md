# 観察メモ

現行計画の[判断の権限と観察](../../README.md#判断の権限と観察2026-10-20採用)と[決定0002](../../decisions/0002-jev-decision-and-visual-observation.md)に基づく、自分側の図形の観察です。参加者向けの初回観察と再観察は Terra が担い、その結果を使って対話行動を決めるのは Jev です。

## 何をするか

**初回観察**では、AI自身の画像と、自分に提示された全図形（新規予備実験では4図形）のIDと画像内の座標（`ownAnchors`）を観察モデルに渡し、図形ごとに次を記録します。

- 見立て（holistic）：全体や部分が何に見えるかの仮説。根拠になった画像の部分を添える。常に仮説として扱う。
- 形の記述（analytic）：形・構成・部分どうしの関係。見立てとは分けて記録する。
- 不明点（unknowns）：まだ分からないこと。

**再観察**は、Jevが図形と論点を指定したときだけ行います。根拠・反証・不明を返し、初回メモには上書きせず追記します。

## 指示文について

初回観察の指示文は、従来の方式と v1 では `observe.ts` の `OBSERVATION_INITIAL_INSTRUCTIONS`、v2 では `initial-observation-generation.ts` の `INITIAL_OBSERVATION_V2_INSTRUCTIONS` です。v1 は名称やカテゴリの例を省いて見立てを求めます。v2 はたとえる範囲を「身近な物や生き物」と示し、馬・牛・鳥などの具体例は省きます。現行計画に出てくる「馬っぽい」は読み手向けの例です。画像に根拠がある見立てを最大8件まで記録し、根拠が見えなければ空でかまいません。指示文の変更は研究者の確認を経てから行います。

## 参加者向けの初回観察の版

`participant_dialogue_v17_pilot012` で承認する受付は `structured_outputs_v2` を使います。v2 は、図形を区別する全体の輪郭・構成・部分の関係と、画像に根拠のある身近な見立てを優先します。JSON Schema とメモの形式は `structured_outputs_v1` と共通です。研究プロキシは指定版の固定指示とスキーマを使います。承認時に保存した方式は両条件の初回観察とキャッシュ照合に適用し、再観察は図形と論点を指定する従来の経路で行います。

| 保存された対話の版 | 発話生成 | Jev の判断材料 | 参照メモリ | 初回観察 |
| --- | --- | --- | --- | --- |
| 旧 v16 | `jev_generation_retry_v16` | 従来の `holistic_v5` の判断材料 | `claim_prune_v2` | `structured_outputs_v1` など承認時に保存した方式 |
| v17（`participant_dialogue_v17_pilot012`） | `jev_generation_retry_v17` | `jev_repair_quality_v1` | `claim_prune_v3` | `structured_outputs_v2` |
| v18（`participant_dialogue_v18_pilot012`） | `jev_generation_retry_v18` | `jev_repair_quality_v1` | `claim_prune_v3` | `structured_outputs_v2` |

承認済みの受付と保存済みの試行は、それぞれに固定された版で開始・復元します。初回観察の方式が保存されていない旧受付には、当時の方式を使います。

v17 では冒頭を Terra が生成し、対話中は Jev が選んだ行動を Terra が発話にします。公開できない稿から回復する場合も、Jev の再判断に沿って Terra が発話を生成します。技術的な失敗時は、対話の発話と区別して再試行できるエラーを表示します。旧版の固定発話は旧版の経路と記録に残ります。

管理用の受付使用量 JSON では、受付承認、先行観察ジョブ、サーバーでの開始要求の受理とメモ取得、試行開始、最初の人発話と応答の時刻を確認できます。サーバー受理はブラウザのクリックとは別の時刻です。

## 初回観察のキャッシュ（2026-10-20採用）

同じ受付内でAI側の描画が同じ試行は、検証済みの初回観察メモを共有します。承認後に先行観察でメモを用意でき、試行開始時に該当するメモがなければ、その場で観察・検証して保存します。照合には、AI側の画像の内容、図形のIDと画像内の座標、観察モデル、指示文、メモの形式の版、初回観察の出力方式を使います。v1 と v2 は別々のキャッシュエントリを使います。キャッシュには相手の画像・正解対応・参加者のデータを含めません。対話中の再観察や合意・否定・名称は、その対話だけのメモに記録します。


## 部分形状の全件記録

`partObservationVersion: tangram_parts_v1` を承認時に明示した受付では、`ObservationInput.ownParts` にAI自側の元7ピースと全連結組合せの幾何情報を渡す。初回モデルの出力JSONとは別にプログラムが検証し、`memo.figures[].parts` へ保存する。`source: own_stimulus_geometry` は生成構造由来の候補を示し、画像上で見える外周と仮の切れ目を `edgeVisibility` で区別する。

初回観察と再観察は候補を画像と照合する。判断用の投影は全候補を残し、公開発話の根拠は該当部分の記述に照合する。候補から相手の指示対象や合意を自動確定しない。保存・復元時は自側のIDと領域、および元ピースから再計算した全候補を検証する。部品版と全候補をキャッシュの識別に含め、旧メモと取り違えない。

### 人手確認した主要領域の事前観察（2026-11-28）
`tangram_parts_reviewed_20261128_v1` を固定した受付は、研究者が確定した全30図形の117領域（0/90/180/270度の120通り・468領域）を用いる。元データは `docs/review/review-results-final.json`（SHA-256: dae9359580d64a8355e0648a822215a4cf8bd77ac9ff4b15623b38a4b288a5cd）。幾何学的な形・面積比・外接範囲・方向・接触関係を計算し、全体と部分の見立てを別の仮説として事前に記録した。見立てはAIの解釈案であり、人手で確認したのは分割であって名称ではない。
`docs/review/build-preobserved-catalog.ts` は上記確定JSONと二つの見立て仮説JSONから、120通りの初回観察メモを含む不変の `primary-regions-data.ts` を生成する。受付承認時に新規の初回観察APIを起動しない。試行開始時は自側の形状・向きに対応するメモだけをロードし、位置とローカルIDを結びつける。対象を特定できない将来の図形に対しては既存の観察経路を利用する。新たな停止・中断・再開条件は追加しない。対話・対象推定・再観察には主要領域の小さい候補集合を渡し、内部保存では元の幾何カタログも保持する。相手側の画像・配置・対応・正解名称・バンクIDを渡さない。二つの対話方略で共通。旧 `tangram_parts_v1` の記録と候補参照の意味は維持する。メモ変更時は新しい版を発行し、既存の版を上書きしない。

この版は承認時に既定では固定しない（#262 の準備済みメモの割当と二者択一になるため）。2026-11-28 以降の新規受付は、次の回転別メモを固定する。

## 回転別メモの pin と開始時の読み込み（2026-11-28）

新規の受付（本番の参加者用実行環境で、参照メモリあり）は、承認時に回転別メモの束を `plan.rotationMemory = { version, dataSha256, catalogRevision }` として固定する（`tangram_rotation_memory_v1`）。束は、確定した分割の幾何と、研究者の確認前のAI案の見立て（全体・独立した部分）から `docs/review/build-rotation-memory.ts` が生成する不変のデータで、見立ての出所は束だけである。この pin が無い旧受付、`preparedObservations`、`partObservationVersion` の計画・記録・キャッシュ鍵は従来のまま変えず、新しい pin はこれらと併用しない。

- **承認**: 準備済みの観察メモを割り当てず、観察の準備（先行観察ジョブ）も積まない。承認が準備待ちに入る経路は無い。
- **開始**: 試行開始時に自側の各図形について、図形の識別と提示中の絶対回転（研究者側の値。モデルへは出さない）から、現在向きを基準にした相対の4方向（現在・時計回り 90/180/270 度）の投影を1回だけ読み、初回メモの各図形の `rotation` として保存する。観察のモデル呼び出し・キャッシュ読み・待ちは無い。束に無い図形は `rotation` の無い素のエントリで続け、停止しない。再観察は従来どおり論点を指定したときだけ行う。
- **初回メモ**: `holistic` は空、`analytic` は見立ての語を含まない定型1行（`rotation-memo.ts`）。旧事前観察テンプレートの見立てや `parts` は入らない。
- **記録と復元**: 記録の `options.rotationMemory = { pin, used }`（pin は plan の pin、used は開始時の配備に入っていた束）。冷復元は保存済みのメモだけを使い、束を読まない。pin と束が合わなくても止めず、`used` に記録する。保存メモの形と初回メモのハッシュは検証する。
- 回転別メモ（投影・凡例・使い方の指示）は、相手の向き・回転方式・相手側の画像・正解対応・図形ID・絶対回転を含まず、参加者にも出ない。課題条件の回転の文と、判断（Jev）の状態にある回転方式は、main から変えていない。両方略に同じ投影を渡す。候補の一致だけで対象・合意・命名を確定しない。
