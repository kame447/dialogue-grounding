## 親が実行するコマンド

`node` は指定の Node v22.23.4 を使う。`CDP_ORIGIN` は親が起動した Chrome、`OUT_DIR` は新しい私有出力先。

```sh
node dialogue-model/runtime/diagnostics/adaptive-human/run.ts --mode offline --out "$OUT_DIR" --cdp "$CDP_ORIGIN" --turns 3 --persona-seed 20261027
node --env-file="$ENV_FILE" --import "$GUARD_MODULE" dialogue-model/runtime/diagnostics/adaptive-human/run.ts --mode live --app "$APP_ORIGIN" --cdp "$CDP_ORIGIN" --out "$OUT_DIR" --turns 4 --persona-seed 20261027 --before-turn-module "$SERIALIZER_MODULE"
```

offline は `--cdp` を `--chrome '<Chrome executable>'` に替えてもよい。live は親が先に P1 server を起動し、既存 runbook の予算・台帳・stage 環境変数を付ける。`SERIALIZER_MODULE` は private の未決済予約が0になるのを待つ async 関数を default export する。harness 自体は台帳を読まない。live の researcher export は親の管理経路で別途保存する。

focused ブラウザ test を既存 Chrome で行う場合:

```sh
ADAPTIVE_HUMAN_CDP="$CDP_ORIGIN" ADAPTIVE_HUMAN_KEEP=1 node --test tests/adaptive-human-e2e.test.ts
```

## Astra の事前確認への対応

親経由で受領した5補足を反映した。決定性は画像を含む可視入力の固定で試験する。名称語だけなら特徴を質問し、明示的な説明を確認しても共同採用や正しい対象同定の成立と扱わない。mock は画像を読まず特徴を捏造しない。harness から simulator への引数に state 本体・scene metadata・event ID・私有資料が混ざらないことをブラウザ test 内で確認する（当該 test の実行は親待ち）。mock の確認発話と仮の understanding は実モデルや人間の理解の oracle にしない。

提出欄は「合成の名前1〜6」、質問紙は技術試験用の仮選択4。終了は `simulator_done` と `turn_cap` を区別する。合成の提出結果・質問紙得点を研究成果や負担の評価として解釈しない。
