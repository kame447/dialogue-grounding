# Common research profile: parity wiring

This Node-only harness applies `RESEARCH_TRIAL_PROFILE_V1` to **new harness trials only**. Historical `createDialogueV2`, `createNamingTaskV2`, v1, web and Workers keep their existing defaults. Both labels run the same Jev pipeline; adoption/rejection intervention is **not implemented**. Independent outputs are not an intervention comparison.

`live.ts` exports `runParityLive(options, dependencies)` and never starts a run on import. The parent owns execution, credentials and live authorization. The implementation's tests use synthetic mocks and local HTTP only; successful mocks do not demonstrate model accuracy or live coverage.

Use `loadRunManifest(privateFile)` to load a repo-external, mode-0600 JSON manifest. `APPROVED_RUN_MANIFEST` describes the approved seed 1701, one figure set, smoke trial plus eight main trials, their order, and engineering budgets. The frozen S0–S3 catalog contains fixed human inputs only, without expected responses or required actions. Custom synthetic scripts are accepted through the API with the same record format. Live execution requires an approved manifest. A manifest is execution data, not independent authorization to call models.

The effective profile adds the manifest's client settings to the frozen base and hashes normalized JSON (sorted object keys, preserved array order). The profile excludes the label. It fixes reference memory, memo-based local grounding, aiPublicClaims, human referent estimation, Jev two-stage decisions, default utterance style and one targeted reobservation. Jev's 15 seconds are shared by both stages of one decision; local and aiPublic each have their own shared 20-second phase budget, observation 20 seconds, generation 40 seconds. A null output-token request means **Worker dependent, effective value unverified**, not an asserted 8192-token guarantee.

Dependencies must construct fresh Luna clients per label and a separate warm-up client. The Luna factory receives `{request, instrumentFetch}`: pass `instrumentFetch(fetch)` to the existing `createChatClient(config, fetchImpl, ...)`. Apply the manifest's `timeoutMs`/`maxCompletionTokens` to config; map null to undefined so environment settings cannot silently override the manifest. A live client without this fetch instrumentation is rejected. `createJevTransport(label)` explicitly supplies `readKey` and `fetchImpl`; the harness never chooses a Keychain reader or reads keys on import. Actual adapters remain separate per trial, preserving their existing USD 0.05 stop rules.

Warm the initial observation cache before either label. MISS creates one validated memo with one observation `complete()` and 1–3 POST attempts (permitted client retries); an existing warm HIT makes no model call. Each trial uses `onMiss: "error"`, records HIT/key/source/memo hash, and makes zero initial-observation POSTs. Targeted reobservation is trial-local. The cache file's byte hash is checked after every trial. Smoke G1 records a current-run MISS; a warm HIT is retained distinctly and does not masquerade as a newly measured creation. Without the required smoke evidence, main trials remain not reached. G2 separates sent/response/model-match/validation and needs one successful basic turn; primary conditional-path errors also block transition. Normal empty/acknowledge skips do not require retries or an induced action.

`audit.ts` maintains one run-wide ledger across warm-up, retries, labels and trials. Complete entries and actual POST attempts are separate. Actual sends reserve unique IDs synchronously before invoking fetch; two-stage Jev bills are accounted before another stage is permitted. Policy GETs are recorded separately. Counts are hard pre-send bounds; observed Jev USD and known Luna input+output tokens are **stop thresholds**, with all already-sent in-flight usage able to arrive later. Every stop records the in-flight IDs and known/unknown consumption at detection. Missing input and output fields are counted separately; known tokens are a lower bound. Luna USD and total USD remain null. Unknown Jev billing stops the whole run and is not reset by new adapters.

The 15-minute trial cutoff blocks new sends and later dialogue commits, including internal Luna retries. It does not assert that upstream computation or billing stopped. Sent outcomes that have not arrived remain unknown; `billing.private.jsonl` records revisions when late consumption is obtained. Those revisions never change a committed dialogue trace. `flushBilling()` waits for currently queued journal writes and returns the latest ledger; it does not wait indefinitely for unresolved upstream work. Keep the process alive if late usage needs to be collected. Snapshot summary totals describe their write time; use the journal/latest ledger for subsequent revisions. Billing-write failures are explicit in `flushBilling()`.

Neutrality is checked by **offline paired replay**: freeze the pre-turn public prefix and state, validated observation results, and recorded Luna/Jev response tapes, then run both labels through the same native runtime/builders/parsers. No extra model calls occur. Exact pre-wire request hashes include instruction bodies and dynamic questions/criteria; context hashes include effective settings and requested/responded models. Body fields are never normalized away. Only the listed envelope fields (`label`, `runId`, transport signal and measurement timestamps/latency) are outside comparison. Reconstruction must also match the original recorded wire hashes. Recorded outputs are fixed inputs for replay, not correctness labels.

Independent trials separately record first public-text and internal-material divergence. A request difference with different upstream materials is not comparable, not a neutrality failure. A missing stage is not reached; identical materials with differing payloads are flagged. Complete instruction-source digests cover private non-exported strings as well as exported prompts; actual sent instructions have per-call hashes too.

Each run uses a new ID in a repo-external directory (0700); records are 0600. Public-only `public-<trial>-<turn>.packet.json` files contain only speaker/turn/text prefixes and their SHA-256, without future turns or private labels/scores/state. The private trial bundle separately contains traces, state/ledger/repair snapshots, wire receipts, replay materials, cache evidence, G1–G4 and technical coverage. Astra freezes public judgments in time order before inspecting private bundles; this harness implements **no semantic scoring**.

Coverage retains stage errors including failed pending, partial source status, individual validated candidate application IDs, source-level rejection reasons, final pending not applied, and repair progress not reached when no next human turn exists. Source-level reasons are not falsely attributed to a specific discarded candidate. Potential contractual rejection reasons are recorded without automatically declaring a broken implementation's rejection legitimate. Public naming agreement and correctness of response links require independent blind review. Paths not selected or extracted remain unobserved, not successful. No historical gates, thresholds, acts, issue rules, intervention or production wiring are changed.
