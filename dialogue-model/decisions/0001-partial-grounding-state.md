# 決定 0001：局所問題・命題単位で共通基盤を部分更新する

- 決定日：2026-10-19（JST）
- 状態：**accepted（設計原則のみ）**。具体的なAPI・閾値・Jevの本番制御および実験条件は未採用／未実装。
- 正本：[現行の研究・実験計画（SSOT）](../README.md)
- 対象：タングラム共同命名の対話判断・参照メモリ・研究用評価。既存の公開実験の挙動を変更する指示ではない。

## 背景と問題

現行の行動選択や「対象同定」「名称合意」の2軸の判定を、図形単位の単一の合意フラグに還元すると、**一部分への同意が別の部分や図形全体への同意に昇格する**危険がある。例えば、形状の一部には一致しながら、向きや見立てにはずれがあり、名称はまだ決まっていないことがある。

過去5対話のM・P・ERおよび発話機能ラベルは、調整が局所的かつ時間的に進むことを検討する材料となる。ただし、a11（同意）、M4（局所のずれ解消）、ER1（エピソード結果）はそれぞれ異なる判定であり、いずれも「すべての図形特徴と名称が合意済み」の十分条件ではない。

## 採用する設計原則

1. **論点を分ける。** 指示対象（同じ図形か）、構成・輪郭などの特徴、向き・位置、何に見えるかという見立て、名前の提案、名前の共同採用、課題の進め方を、異なる局所問題として識別する。同じ図形に複数の未解決問題が残ってよい。
2. **更新は部分的・非破壊的に行う。** 同意、否定、訂正、保留、再訪は、出典が結び付いた対象・局所命題だけに適用する。別の命題や同じ図形全体へ自動伝播させない。対立する根拠は無言で上書きせず、出典付きで競合・撤回を追跡する。
3. **「理解している」「同意した」の対象を明示する。** 「はい」「それでいい」は直前のどの提案への応答かを先行文脈で特定できた場合にだけ更新する。対象候補が複数、または回答枠が不明なときは未確定を保つ。別の図形の名称への同意を現在図形の合意に流用しない。
4. **見立てと命名を分ける。** 「船みたいに見える」は見立ての表明であり、それだけでは名称提案ではない。「この図形を『船』と呼ぼう」は命名提案となる。名前の共同採用は、その名前への相手の適切な受諾が確認できるまで成立扱いしない。
5. **保留や曖昧さを保持できる。** 部分的に共有した点は残し、未確認・争点のある点を保留したまま別対象へ進んだり、後から同じ局所問題へ戻ったりできる。未確定点があること自体は常に修復を強制する理由ではない。
6. **研究上の採点と分離する。** AI内部の「共有した可能性」と真の図形対応・最終名称の一致は別物。最終の課題成功は、参加者双方の提出を独立に照合して評価する。

## 記憶状態の概念モデル（新規コードの型は未確定）

局所問題ごとに、次の情報を扱う。**既存の参照グラフを拡張・集約する方向**であり、並行する別の「正しい記憶」を新設するものではない。

| 項目 | 内容 |
| --- | --- |
| 局所問題ID・対象候補 | 同じ話題へ再訪できる安定IDと、AI側であり得る図形候補。対象が曖昧なら複数候補／未特定を許す |
| 論点 | 指示対象、特徴（該当部分）、向き、位置、見立て、名称候補、名称採用、進行方針など |
| 命題・関係 | 何を肯定・否定・質問しているか。発話の自由記述部分はLuna等が仮抽出する |
| 局所状態 | 未確認、支持あり、否定あり、競合、保留、撤回済みなど。名称については `no_name` / `unclear` / `not_agreed` / `agreed` / `unknown` を区別 |
| 根拠・来歴 | 公開発話番号、話者、対応する発話部分、先行する提案との参照関係、更新履歴 |
| 認識上の位置付け | 本人の観察、相手の言明、AIの仮説を区別。AIが推定した対象対応は正解ではない |

既存の `referenceGraph` の `mention`（epistemic/intent/antecedent）、`feature`、`name`（agreement）、`question`（open/deferred/resolved）、`focus`（defer/revisit）、`retract` をなるべく利用する。現行の `grounded` は**公開発話をAIが自分側の候補へ対応付けた解釈**であり、実際の相手側図形との正解照合や図形全体の同意ではない。

## 想定する処理順序（設計案。既存の動作とは異なる）

1. **Luna：文脈付きの意味解釈。** 公開済みの直前・先行発話とAI自身の画像・参照メモリから、発話内の独立した節／部分、対象候補、局所問題、命題・先行発話へのリンクを提案する。相手専用画像や正解表は入力しない。
2. **Jev：閉集合の局所判断。** 各部分について、何への応答か、受容／同意／否定／質問／命名提案／名称受諾／保留／再訪などの機能、どの論点への作用かを分類する。a系発話機能は研究用の参考区分であり、語形だけでa11・a12などを確定しない。入力が不足する場合は `unknown` / review に残し、確信度スコアを正答確率と呼ばない。
3. **プログラム：出典を検証し、局所差分のみ適用。** 対象候補・論点・引用元・矛盾／撤回関係を確認できた更新だけを、対象の局所状態へ適用する。一つの発話で複数の部分が変わってよい。確認不能なら保留し、他の既知情報は維持する。内部の先行判断や未公開の生成予定を「相手も合意した」証拠にはしない。
4. **Luna：次の応答を自然に生成。** 確定している部分と未解決の部分を区別した記憶を参照し、方略に従い、必要に応じて確認・修復・保留・進行・再訪を選ぶ。固定テンプレート文の反復や、局所合意だけを根拠にした「全部分かりました」は避ける。
5. **コミット。** 実際に公開された発話だけを履歴・メモリの出典とする。生成失敗・置換・中断時に未公開の応答や不成立の同意を反映しない。最終採点は別経路で実施する。

機能と論点を一度にJevへ質問するか、抽出→局所機能判定→関連付け→状態更新に分けるかは、誤判定・遅延・費用を測って決める。**この段階でJevの閾値や数値的な合意率を強制する案は採用しない。**

## 局所更新の例

| 公開発話・場面 | 更新してよい部分 | 更新しない部分 |
| --- | --- | --- |
| 「四角い部分はあります」「そう、それ」 | 当該四角の特徴について支持の根拠を追加（指示対象が追える場合） | 図形全体の同定、向き、見立て、名前 |
| 「でも三角は上じゃなくて下」 | 三角の上下関係について反証・訂正を記録 | 既に支持された別の四角の特徴 |
| 「船みたい」「いや、船には見えない」 | 「船のように見える」という**見立て**の相違を記録 | 明示的に名前を採用・拒否したという履歴を勝手に作らない |
| 「この図形を『船』と呼ぼう」「うん」 | 先行の命名提案への受諾だと確証できれば、その対象の名称採用の根拠を追加 | 相手と同じ実物を指している正しさ、別の未確認特徴 |
| 「向きはまだ分からないけど、次へ進もう」 | 向きの疑問を保留し、進行・再訪の焦点を記録 | 既に確認した特徴、保留中の論点の解消 |

例は**機能を示す合成発話**であり、元の参加者データの引用や追加の実験刺激ではない。

## 現行実装との境界

- 現行v2の `ownLedger`、参照グラフ、Jevの対象同定／名称合意2軸シャドーはこの部分更新方式を全面的に実装したものではない。今回の決定は**ドキュメントのみ**で、既定の実験条件・プロンプト・API・メモリ挙動・採点・公開UI・デプロイに影響しない。
- 両方略（repair-first / bypass-enabled）に同じ意味解釈・部分更新機構を使用し、違いは次の対話行動の方略に限定する。「保留が多い」ことを成功とせず、成功率・認知負担・円滑さを別々に観察する。
- 現行ラベルは、単一図形の状態ではなく、局所のずれ（M）、調整過程（P）、エピソード結果（ER）、発話の機能（a）の**異なる分析水準**を表す。提案スキーマへ機械的に置き換えない。

## 検証計画と保留事項

- **ローカルの合成対話で回帰確認：** 同一発話内の「特徴は同意／向きは否定」、短い相槌の指示先、別対象の名称受諾、見立てと命名の区別、保留・再訪・撤回、重複候補、復元、生成失敗時の非コミットを確認する。
- **過去5対話での検討：** M0–M4、P1–P5、ER0/ER1、a1/a3/a4/a8/a11/a12などの付与箇所を、直前・直後と同じ局所問題の系列を読んで比較する。見立てへの受容、名称の受諾、対象同定を別に評価する。ラベルが空欄なら「ずれなし」と決めず、独立した追加アノテーションを必要に応じて実施する。
- **測定単位：** 局所問題ごとの検出・誤更新率、意図しない全体への昇格、保留・再訪の成否、過剰確認、最終提出一致、応答遅延、主観的負担・円滑さを区別する。
- **ホールドアウト：** 開発に使った対話・場面をそのまま検証の正解にしない。対話／エピソード単位で分離し、必要なら別評価者の独立ラベルと誤差分析を行う。
- **未決定：** 局所問題IDの切り方、発話部分の抽出精度、対象候補のリンク閾値、否定時の更新条件、implicit合意の扱い、JevのChoice/Scoreや確信度校正、実際の行動への利用時点、実験への採用時期。これらを本書で確定したとみなさない。

## 代替案と採用理由

- **図形ごとの合意フラグを一括更新する案：不採用。** 部分的な理解と残ったずれを区別できず、過早な合意を生む。
- **不確実な点はすべて即時確認する案：不採用。** やり過ごし・次善的合意・後からの修復を検討する研究目的に反する。
- **局所情報をすべてJevで抽出・確定する案：不採用。** 任意の発話部分・参照先・命題は自由記述と文脈解釈を要する。生成モデルの候補抽出と閉集合判断、プログラムによる出典検証を分離する。

採用したのは**部分更新と責務分離という設計原則**であって、具体的モデル構成の有効性を立証したわけではない。
